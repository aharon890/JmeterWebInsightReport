# Web Insight Report vs JMeter's HTML report: accuracy findings

**What this is.** The tracker of every way the Web Insight Report (WIR) differs from JMeter's own HTML report
of the same `results.jtl`. It comes from the accuracy campaign in `petstore_ms/tmp/wir-metrics-verification/`, owner
decision D1: JMeter's HTML report is the one reference for the Summary, Samplers, Errors and Timeline tabs.

- **Live results:** https://claude.ai/artifact/2iMrivbZqEB5vuMGM9fApV (every case, every difference, filters, CSV).
- **Plan and method:** https://claude.ai/artifact/WQbdE4jw8YxLxehcUpspoq.
- **In every petstore plan build:** the "JMeter vs Web Insight Report" link (petstore PR #74).
- **Generated** 2026-10-29 from the campaign's results by `tools/findings-to-plans-md.mjs`. Regenerate it rather than editing the tables.

## The campaign

64 of 65 cases checked: 47 no-server runs (controlled fake requests: lengths from 30 s to
2 h, 1 to 1,000 threads, up to 2,000 requests/s, response-time profiles, error kinds, transaction controllers, 500
labels, results-file settings) and 17 petstore runs (the real plans at several loads and lengths). WIR 4.2.0.

| Tab | Checks equal | Checks made | Share equal |
|---|---|---|---|
| Summary | 760 | 1,012 | 75.1% |
| Samplers | 15,829 | 17,206 | 92.0% |
| Errors | 3,977 | 5,314 | 74.8% |
| Timeline (points, JMeter placing by start) | 2,837,941 | 3,241,288 | 87.6% |
| Display (points drawn) | 3,767,722 | 3,781,199 | 99.6% |

Every difference found is explained by one of the findings below (11,797 explained, 0 not).

**Equal to JMeter in every case without transaction controllers or sub-results** (and apart from the two cases that
change how results.jtl is written, S45 and S46): samples, errors, error %, mean, min, max, throughput, KB/s, start,
end, duration, and every per-second chart value once JMeter places requests by start time. Percentiles (F3) and
the chart drawing (F5, F13-F15) are where those cases differ.

## Re-running

- One case: `node tools/run-case.mjs <case>` in the campaign folder (cases in `cases.csv`).
- With a dev jar: put it in the campaign JMeter's `lib/ext` instead of the 4.2.0 jar and rerun the cases a finding
  names; the finding is fixed when those cases no longer show it.
- Any petstore run: `scripts/jmeter/compare-with-jmeter.sh <plan>` (after petstore PR #74).
